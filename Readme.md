# Метрики и лейблы

`http_request_duration_seconds` — histogram, время запроса в секундах. Лейблы: `pod`, `datacenter`, `handler`.
`http_requests_total` — counter, число ответов. Лейблы: `pod`, `datacenter`, `handler`, `status`.
`handler` — метод и шаблон пути, например `GET /items/{item_id}`. `pod` и `datacenter` приходят из переменных `POD_ID` и `DATACENTER`.
RPS считается как `sum(rate(http_requests_total[1m]))`. Ошибки — тот же счётчик, только со статусами 4xx и 5xx.

## Почему latency — histogram
Summary считает перцентиль внутри одного процесса. Два таких числа с разных подов нельзя сложить и получить общий перцентиль также как нельзя сложить номера телефонов.
Histogram хранит бакеты, сколько запросов попало в каждую границу `le`. Одинаковые бакеты с нескольких подов суммируются и `histogram_quantile` считает перцентиль уже по этой сумме. Поэтому p50, p95 и p99 остаются корректными, когда на дашборде выбраны оба пода.
